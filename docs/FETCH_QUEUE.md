# Очередь на загрузку документов

Список продуктов и адресов не хранится в этом файле — он генерируется из
карточек, чтобы не разъезжаться с ними:

```bash
python -m matdb queue
```

Здесь — почему очередь вообще существует и что с ней делать.

## Почему документов нет

Сетевая политика окружения, в котором собирался проект, пропускает практически
только GitHub. Домены производителей и агрегаторов документации — `isomat.eu`,
`alchimica.com`, `sika.com`, `mapei.com`, `triflex.com`, `tn.ru`,
`datasheets.tdx.henkel.com`, `archiexpo.com` — возвращают 403 на этапе CONNECT.
Проверено напрямую, обходить это запрещено инструкцией прокси.

Поэтому **ни один TDS не открыт**. Адреса получены из результатов поиска
(заголовки и ссылки на страницы производителей), а не из самих файлов.

Отсюда ограничение, которое надо держать в голове: **адрес найден, содержимое не
проверено.** Ссылка может вести на устаревшую редакцию, на соседний продукт
линейки или на страницу дистрибьютора с перепечаткой. Прежде чем извлекать
числа, файл надо открыть и убедиться, что это тот продукт и та редакция.

Карточки, где сама ссылка вызывает сомнения, помечены об этом в `status_note`.

## Почему в карточках нет чисел

Поисковая выдача возвращала конкретные значения: расход, предел влажности
основания, межслойный интервал. Ни одно не внесено в базу.

Причина не в осторожности вообще, а в том, что пересказ поисковой системы не
является источником: неизвестна страница, неизвестна редакция и неизвестно, к
какому варианту продукта относится число. Показательный случай — тот же расход
«1,0–1,5 кг/м²» выдавался одинаково и для ISOFLEX-PU 500 THIXO, и для DTL, хотя
это разные материалы.

Записанное таким образом значение стало бы неотличимо от извлечённого из
документа — ровно то, против чего построена вся модель данных. Тест
`test_no_placeholder_numbers_leaked_into_data` следит, чтобы этого не случилось
и впредь.

## Порядок работы с документом

```bash
# 1. Скачать в tds/<производитель>/<продукт>.pdf — каталог в .gitignore,
#    чужие документы в репозиторий не кладём
# 2. Разобрать в черновик карточки
python tools/extract_tds.py tds/isomat/isoflex-pu-500.pdf \
    --id isoflex-pu-500 --revision <как напечатано в документе> --write
# 3. Сверить каждую цитату из отчёта с документом
# 4. Проставить status=verified, verified_by, verified_at
```

Шаг 4 не автоматизируется. Он и есть содержание работы: извлечение занимает
минуты, а ответственность за число берёт тот, кто его подтвердил.

## С чего начинать

1. **`ceresit-cr-166` и `ceresit-cr-65`** — единственные две ссылки, ведущие
   напрямую на PDF с русскоязычным TDS. Разбор пойдёт сразу, без поиска по сайту.
2. **`isoflex-pu-500`** — с него начинался проект.
3. Дальше по семействам: имеет смысл закрывать целиком одно семейство, чтобы
   сразу видеть разброс параметров внутри него.

## Варианты внутри линеек

Частая ловушка: продукты одной линейки выглядят как один материал, а являются
разными, с разными пределами. Подтверждённый пример — ISOMAT:

| Вариант | Что это |
|---|---|
| ISOFLEX-PU 500 | Базовая жидкая мембрана для плоских кровель |
| ISOFLEX-PU 500 A | Ускоренного отверждения |
| ISOFLEX-PU 500 THIXO | Тиксотропная, для вертикальных и наклонных поверхностей |
| ISOFLEX-PU 500 DTL | Армированная волокном, для примыканий и узлов |
| ISOFLEX-PU 560 BT | Отдельный продукт линейки |

Заведена карточка только на базовый ISOFLEX-PU 500. Остальным нужны свои —
переносить параметры между вариантами нельзя, у «A» одни только времена
отверждения заведомо другие.

То же относится к линейкам HYPERDESMO, Sikalastic, Ucrete и Mapelastic:
в базе заведена часть, не весь ассортимент.

## Чего в базе пока нет

Семейства из справочника, под которые не заведено ни одного продукта:

- `bitumen`, `bitumen_polymer` — рулонные и мастичные битумные материалы
- `silane_siloxane` — гидрофобизаторы
- `silicate` — упрочняющие пропитки
- `ms_polymer`, `silicone` — герметики
- `acrylic_wb`, `epoxy_wb`, `pu_2k`

Правила совместимости для них есть — они нужны, чтобы отвечать на вопросы про
основания и соседние слои. Карточек продуктов нет.
